What changes when voice arrives

Only hops 01, 09 and 10. A call replaces the POST with a WebSocket frame from ConversationRelay, and the token stream goes to text-to-speech instead of a browser. Steps 02–08 and 11–12 are identical, because they are the same function — which is the whole reason the bench is worth having: it proves that claim at runtime rather than asserting it in a comment.

Part A — test what works today

1Start everything

From ~/code/tac-langfuse:

pnpm langfuse    # only if it is down — 6 containers, ~10s on warm volumes
pnpm dev:all     # agent :8910 + web :3000, ctrl-c stops both

Give it ~20 seconds, then pnpm status. You want green on agent, web and langfuse. Voice and SMS reading as unavailable is correct.

2Open the bench and send two messages

http://localhost:3000/bench — the home page at / is still a placeholder. Type the first, wait for the answer, then the second:

Where is order A4721, and what are the Downtown store hours?
What was the order number I just asked about?

Nothing in that second sentence contains the order number, so a reply of A4721 is history working. If it asks which order you mean, something regressed — worth telling me.

3Read the footnote under each answer

v2 · gpt-5.4-mini · first token 1452ms · total 2097ms · 2 steps · lookup_order, get_store_hours
  • v2 — which Langfuse prompt version answered. Shows fallback if Langfuse was unreachable and the compiled-in default was used.
  • first token — measured from the start of the turn, so it includes prompt fetch and tool resolution, not just the model call.
  • steps — 1 is a plain answer, 2 means one tool round-trip.

Expect turn 1 around 1.5–2.3s to first token and turn 2 around 0.5s with 1 step. That gap is the tool loop's cost, made visible.

4Find the trace in Langfuse

http://localhost:3100, signing in with LANGFUSE_INIT_USER_EMAIL / LANGFUSE_INIT_USER_PASSWORD from your .env — no signup step. Then Scaffold → Tracing, newest conversation.bench: 

conversation.bench
├─ turn.bench                       2.10s
│  └─ llm.stream → invoke_agent → chat gpt-5.4-mini ×2    tool loop
└─ turn.bench                       0.59s
   └─ llm.stream → invoke_agent → chat gpt-5.4-mini ×1    answered from memory
Expect this, it is not a bug

A conversation.bench root only appears once the conversation ends — held open for 30 minutes of idle, or until the agent shuts down. Individual turns appear promptly. Stopping the agent flushes it.

Part B — gather the Twilio credentials

Seven values, in three groups. .env.example in the repo is the authoritative version of this table — it documents each variable's Console location, format, and what breaks without it, and a test fails if the code reads a variable that file does not describe.

Group 1 — the core five. All of them, or no channel starts at all.

VariableWhereFormat / gotcha
TWILIO_ACCOUNT_SIDConsole → Account → API keys & tokensAC + 32 hex
TWILIO_AUTH_TOKENConsole → Account → Auth Token (click to reveal)Also validates the X-Twilio-Signature on every inbound webhook, so a wrong value looks like “Twilio is 403-ing us” rather than a bad secret
TWILIO_API_KEYConsole → API keys & tokens → Create API keySK + 32 hex. Standard is enough
TWILIO_API_SECRETShown once at key creationNot retrievable later — lost means make a new key
TWILIO_PHONE_NUMBERConsole → Phone NumbersE.164, e.g. +15551234567. A 555-1234 here is a common and confusing failure

TACConfig.fromEnv() throws if any one of these five is missing or malformed, which is why server/config.ts validates them itself and only constructs TAC once all five are good.

Group 2 — voice

TWILIO_VOICE_PUBLIC_DOMAINYour public host — on the Traefik dev box, <APP_NAME>.twilio.dtolb.comBare host, no scheme. https://x.com is rejected; x.com and x.ngrok.app:8080 are fine. TACServer throws at construction without it. The dev box already terminates TLS, so no ngrok needed

Group 3 — orchestrated mode (required for SMS, memory, handoff, knowledge)

TWILIO_CONVERSATION_CONFIGURATION_IDConsole → Products & services → Conversation Orchestrator → Conversation configurationsconv_configuration_… — new SMSChannel(tac) throws without it and does not degrade to a no-op. One thing that will confuse you

Your shell profile already exports TWILIO_ACCOUNT_SID, TWILIO_API_KEY and TWILIO_API_SECRET, so those three read as present in pnpm status and /health whether or not they are in .env. Only the other four will show as missing. That is real, not a bug — but it means .env is not the whole picture on this machine.

Part C — verify each credential before the app needs it

Do this with the Twilio CLI, not with the scaffold. Every check below is read-only and none of them place a call or send a message.

1Confirm the CLI is using the credentials you think it is

twilio profiles:list

A profile shown as [env] means the CLI is reading your exported environment variables rather than a stored profile — worth knowing, because editing .env will not change what the CLI sees.

2Prove the key and secret authenticate

twilio phone-numbers:list
Do not use accounts:list for this

The obvious check, twilio api:core:accounts:list, returns HTTP 401, error 70004 — “the provided key does not have the permissions to access this endpoint” — on a restricted API key, even when the key is perfectly good. Confirmed on this account. It reads as “my credentials are wrong” and sends you rotating keys that were fine. phone-numbers:list exercises the same credentials against an endpoint a restricted key can actually reach.

The listing also gives you the exact E.164 string for TWILIO_PHONE_NUMBER, and shows whether each number is voice- and SMS-capable.

3Find or confirm the Conversation Orchestrator configuration

This one has no CLI command, so call the API directly:

curl -s -u "$TWILIO_API_KEY:$TWILIO_API_SECRET" \
  https://conversations.twilio.com/v2/ControlPlane/Configurations \
  | python3 -m json.tool

Each entry has an id (conv_configuration_…) and a memoryStoreId. A configuration without a memory store gives you SMS but no Conversation Memory, so check that field rather than assuming. If you have none, the Console quickstart creates the configuration and the memory store together — Conversation Orchestrator quickstart.

4Confirm the Studio handoff flow

twilio api:studio:v2:flows:list

You want a flow whose status is published; a draft SID will not behave. Copy its FW… SID.

5Verify the auth token separately — it is the one that bites

The auth token is not interchangeable with the API key. It is what validates inbound webhook signatures, so a stale one produces “Invalid Twilio webhook signature” on every single inbound request and looks exactly like a Twilio outage. Because it is only readable in the Console, the check is to use it as HTTP Basic auth in place of the key pair: 

curl -s -o /dev/null -w '%{http_code}\n' \
  -u "$TWILIO_ACCOUNT_SID:PASTE_AUTH_TOKEN_HERE" \
  "https://api.twilio.com/2010-04-01/Accounts/$TWILIO_ACCOUNT_SID/IncomingPhoneNumbers.json?PageSize=1"

200 means the token is good. 401 means you copied the wrong value or a rotated one. Do not leave the token in your shell history — paste it into .env instead and re-run using $TWILIO_AUTH_TOKEN.

6Then check the scaffold agrees

pnpm status                          # capability flags
curl -s http://localhost:8910/health # same flags, plus every missing var by name

/health names the specific variables it is missing, which is the fastest way to catch a typo'd key name. Note that a value in your shell environment satisfies it just as well as .env.

Part D — what still has to be built

Credentials alone will not light up a phone. In order:

  • T12 — SMS. Register the SMS channel, memoryMode: 'always', return a string from onMessageReady and never throw from it (TAC swallows those errors and only logs them, which is a silently unanswered customer).
  • T13 — Voice. The high-risk one. The voice channel is passed to TACServer but deliberately not registered, because registerChannel consumes the prompt slot and later taps silently replace TAC's handler. Also: start the conversation span on setup and stash the traceparent on session.metadata, which is the only cross-turn carrier that exists.
  • T14 — the Twilio built-in tools. Each construction guarded individually, so a missing handoff flow costs you one warning instead of dead air.
  • T15–T17 — Docker, Traefik, dev overlay.

Part E — two deploy traps already documented

Not needed until T15, but they are the ones that waste an afternoon:

X-Forwarded-Proto will 403 every webhook

TAC rebuilds the signed webhook URL from the X-Forwarded-Proto header, defaulting to https only when it is absent. Traefik terminates TLS and forwards http, so TAC validates http://… against a signature Twilio computed over https://…. Every voice and SMS webhook 403s with one warning that reads like a Twilio problem. The fix is a Traefik middleware label forcing the header to https — correct rather than a hack, since the public door is always HTTPS.

Traefik router names are global on the box

Two clones both left at APP_NAME=scaffold define routers with identical names, and one demo silently steals the other's Twilio webhooks. Nothing errors. Set APP_NAME first, before anything else — the preflight script refuses to bring the stack up while it is still the default.
